**One queue, any language.** The bunqueue server does all the heavy lifting —
retries, priorities, scheduling, dead letter queue. Your apps just add jobs
and process them, from whatever language they're written in.

| Where your code runs | What to install | Get it |
|---|---|---|
| Node.js, Deno, Bun, Cloudflare Workers | `npm install bunqueue-client` | [**npm →**](https://www.npmjs.com/package/bunqueue-client) · [source](https://github.com/egeominotti/bunqueue/tree/main/sdk/typescript) |
| Python | `bunqueue-client` (PyPI coming soon) | [source + install →](https://github.com/egeominotti/bunqueue/tree/main/sdk/python) |
| Bun (same process, no server) | `bun add bunqueue` | [Quick Start](/guide/quickstart/) |

Everything on this page is verified by the SDK test suites against a real
server: **81 e2e scenarios on each of Node.js, Deno and Bun**, plus **16 inside
workerd** (the actual Cloudflare Workers runtime) and **57 in Python** — every
public method of the SDKs is covered by at least one real test.

## 1. Start the server

```bash
bunx bunqueue start
# or, with Docker and persistent data:
# docker run -d -p 6789:6789 -p 6790:6790 -v bunqueue-data:/app/data ghcr.io/egeominotti/bunqueue:latest
```

That's it — the queue is listening on port 6789. (More options in
[Running the Server](/guide/server/).)

## 4. Process jobs

<Tabs>
<TabItem label="Node / Deno / Bun">

```typescript
import { Worker } from 'bunqueue-client';

const worker = new Worker('emails', async (job) => {
  await sendEmail(job.data.to);
  return { sent: true };
});

worker.on('completed', (job) => console.log('done:', job.id));
```

</TabItem>
<TabItem label="Python">

```python
from bunqueue import Worker

def process(job):
    send_email(job.data["to"])
    return {"sent": True}

Worker("emails", process, concurrency=10).run()
```

</TabItem>
</Tabs>

Run either file with the runtime you already use:

```bash
node --experimental-strip-types app.ts    # Node 22+
bun app.ts                                # Bun
deno run -A app.ts                        # Deno 2+
python app.py                             # Python
```

Done. The producer and the worker can be **different apps in different
languages** — a Next.js API adding jobs, a Python service processing them.

## Everything else is one line away

Failures retry automatically (3 attempts by default). After that, jobs land
in the [dead letter queue](/guide/dlq/) — nothing is ever lost.

```typescript
// Priority, delay, custom retries
await queue.add('report', data, { priority: 10, delay: 5000, attempts: 5 });

// Run something every morning at 9:00
await queue.addCron('daily-report', '0 9 * * *', { type: 'report' });

// Give up immediately on bad input (straight to DLQ, no retries)
throw new UnrecoverableError('malformed payload');

// Chain steps: extract → transform → load
await flow.addChain([
  { name: 'extract', queueName: 'etl' },
  { name: 'transform', queueName: 'etl' },
  { name: 'load', queueName: 'etl' },
]);

// Production: auth + TLS
new Queue('emails', { host: 'queue.example.com', token: '...', tls: true });
```

Same one-liners in Python with snake_case names (`add_cron`, `add_chain`, …).

## Simple Mode, everywhere

Prefer everything in one object? [Simple Mode](/guide/simple-mode/) is in the
SDKs too, 1:1 with the original: routes, middleware, in-process retry
strategies, circuit breaker, batching, triggers, TTL, cancellation.

<Tabs>
<TabItem label="Node / Deno / Bun">

```typescript
import { Bunqueue } from 'bunqueue-client';

const app = new Bunqueue('notifications', {
  routes: {
    'send-email': async (job) => ({ sent: true }),
    'send-sms': async (job) => ({ sent: true }),
  },
  concurrency: 10,
  retry: { maxAttempts: 5, strategy: 'jitter' },
  circuitBreaker: { threshold: 5, resetTimeout: 30_000 },
});

app.use(async (job, next) => {
  console.time(job.name);
  const result = await next();
  console.timeEnd(job.name);
  return result;
});

await app.add('send-email', { to: 'alice@example.com' });
await app.cron('daily-digest', '0 9 * * *', { to: 'all' });
```

</TabItem>
<TabItem label="Python">

```python
from bunqueue import Bunqueue

app = Bunqueue(
    "notifications",
    routes={
        "send-email": lambda job: {"sent": True},
        "send-sms": lambda job: {"sent": True},
    },
    concurrency=10,
    retry={"max_attempts": 5, "strategy": "jitter"},
    circuit_breaker={"threshold": 5, "reset_timeout": 30000},
)

def timing(job, next_fn):
    result = next_fn()
    print(f"{job.name} done")
    return result

app.use(timing)

app.add("send-email", {"to": "alice@example.com"})
app.cron("daily-digest", "0 9 * * *", {"to": "all"})
```

</TabItem>
</Tabs>

The only difference from the Bun original: `embedded: true` is not available
(it needs the in-process Bun runtime) — connect to a server instead.

## Cloudflare Workers

The same client runs inside Workers — enable Node.js compatibility and add
jobs straight from your fetch handlers:

```toml
# wrangler.toml
compatibility_flags = ["nodejs_compat"]
compatibility_date = "2025-01-01"
```

```typescript
import { Queue } from 'bunqueue-client';

export default {
  async fetch(req: Request, env: Env): Promise<Response> {
    const queue = new Queue('signups', { host: env.BQ_HOST, port: 6789, token: env.BQ_TOKEN, tls: true });
    const job = await queue.add('welcome', await req.json());
    queue.close();
    return Response.json({ queued: job.id });
  },
};
```

Workers are request-scoped, so there is no long-lived worker loop: **produce
from fetch handlers, consume in batches from a
[Cron Trigger](https://developers.cloudflare.com/workers/configuration/cron-triggers/)**
(pull → process → ack, then return). Both patterns are covered by the SDK's
16-scenario suite that runs inside workerd — including Simple Mode. Two
requirements: your server must be reachable from the internet and TLS needs
a publicly trusted certificate.
