  <span class="bq-eyebrow">persistence</span>
  <h2 class="bq-h2">One process. One file.</h2>
  <div class="bq-file">
    <p class="bq-lede">Everything the queue knows lives in <code>bunq.db</code>: jobs and their states, schedules, results, the dead letter queue. Back it up with <code>cp</code>, inspect it with <code>sqlite3</code>, ship it to S3 on a schedule. Your infrastructure diagram loses three boxes, and there is no version skew between the queue and its store.</p>
    <pre class="bq-tree">production/
├── app/                  <i>your services</i>
└── data/
    └── <b>bunq.db</b>           <i>the entire queue</i>
        · jobs            <i>waiting · active · completed</i>
        · cron            <i>schedules and repeatables</i>
        · dlq             <i>failed jobs, kept</i>
        · results         <i>return values</i></pre>

<div class="bq-wrap bq-section">
  <span class="bq-eyebrow">developer experience</span>
  <h2 class="bq-h2">A queue and a worker, ten lines.</h2>
  <p class="bq-lede">Familiar Queue and Worker API, end to end TypeScript, and 3.5x the bulk push throughput of BullMQ measured on identical workloads, methodology below. Migrating takes minutes, the mental model is the same.</p>

  <div class="bq-terminal">
    <div class="bq-terminal-bar">
      <span class="bq-dot" style="background: var(--bq-red)"></span>
      <span class="bq-dot" style="background: var(--bq-amber)"></span>
      <span class="bq-dot" style="background: var(--bq-green)"></span>
      <span style="margin-left: 0.5rem">app.ts</span>
    </div>

```typescript
import { Queue, Worker } from 'bunqueue/client';

const queue = new Queue('emails', { embedded: true });

await queue.add('welcome', { to: 'user@example.com' }, { attempts: 3 });

const worker = new Worker('emails', async (job) => {
  await sendEmail(job.data);
  return { sent: true };
}, { embedded: true, concurrency: 5 });

worker.on('completed', (job, result) => console.log(`done: ${job.id}`));
```
