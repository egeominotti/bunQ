## Automatic Retry

With `autoRetry` enabled, bunqueue re-queues DLQ entries on its own, spacing retries out with exponential backoff (each retry waits twice as long as the previous one):

<Tabs syncKey="lang">
<TabItem label="Bun">

```typescript
queue.setDlqConfig({
  autoRetry: true,
  autoRetryInterval: 60000,  // base delay: 1 minute
  maxAutoRetries: 3,
});
// 1st retry: 1 min after entering the DLQ
// 2nd retry: 1 min after the 1st  (60s x 2^0)
// 3rd retry: 2 min after the 2nd  (60s x 2^1)
// After that the entry stays in the DLQ permanently
```

</TabItem>
<TabItem label="Node.js / Deno">

```typescript
await queue.setDlqConfig({
  autoRetry: true,
  autoRetryInterval: 60000,  // base delay: 1 minute
  maxAutoRetries: 3,
});
// 1st retry: 1 min after entering the DLQ
// 2nd retry: 1 min after the 1st  (60s x 2^0)
// 3rd retry: 2 min after the 2nd  (60s x 2^1)
// After that the entry stays in the DLQ permanently
```

</TabItem>
<TabItem label="Python">

```python
# Config keys are the wire names (camelCase)
queue.set_dlq_config({
    "autoRetry": True,
    "autoRetryInterval": 60000,  # base delay: 1 minute
    "maxAutoRetries": 3,
})
# 1st retry: 1 min after entering the DLQ
# 2nd retry: 1 min after the 1st  (60s x 2^0)
# 3rd retry: 2 min after the 2nd  (60s x 2^1)
# After that the entry stays in the DLQ permanently
```

</TabItem>
</Tabs>

*The PHP, Go, Rust, and Elixir SDKs do not expose DLQ configuration helpers yet. The config lives server-side per queue, so setting it once from any TypeScript or Python client applies to jobs produced and consumed in every language.*

A background task checks for due retries every minute and re-queues jobs with a reset attempt count.
